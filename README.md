# ARCHI-TACT משרד

ניהול משרד אדריכלות: שלבים, אישורי לקוח, דרישות תשלום ותזרים. מהשלב, דרך אישור הלקוח, אל התשלום.

כתובת: https://archi-tact-misrad.vercel.app

## הרצה
```
npm install
npm run dev        # פיתוח
npm run build      # בדיקת טיפוסים ובנייה
npm test           # Playwright מול vite preview (אחרי build)
```

## מבנה
- `src/domain`: מודל הנתונים (`types.ts`), מכונת המצבים של שלב, סיכונים, תזרים ומדדי אמינות (`logic.ts`), קישורי פורטל (`share.ts`), נתוני הדגמה ותבנית שלבים (`seed.ts`).
- `src/store/store.tsx`: מקור נתונים אחד, שמירה ב-localStorage בכל שינוי, סנכרון לענן, מצב עריכה והודעות.
- `src/cloud/api.ts`: קריאות לפונקציות msr_ והודעות שגיאה בעברית.
- `src/components`: הסרגל העליון וכפתור הלוגו A&I, רכיבי ממשק, ויזואליזציות (מסילת שכר הטרחה, צינור בנייה-גשר-תשלום, תזרים, גיול, טבעת).
- `src/pages`: בית, משרד, פרויקט, תזרים, דרישת תשלום, פרויקט חדש, הגדרות, פורטלים.
- `tests/e2e.mjs`: בדיקת קצה לקצה.
- `docs/SPEC.md`: האפיון.

## החלטות
- מקומי קודם: הנתונים תמיד נשמרים במכשיר (localStorage), עם ייצוא וטעינת גיבוי.
- ענן לבחירה (הגדרות, "חיבור המשרד לענן"): Supabase בפרויקט cultura-GH, טבלאות msr_ סגורות, גישה רק דרך פונקציות msr_ עם מפתח משרד פרטי. ראו `supabase/migrations`.
- מחובר: קישורי לקוח וקבלן קבועים (`/c/TOKEN`, `/k/TOKEN`), הלקוח מאשר ישירות, והאישור מוציא דרישת תשלום בסנכרון הבא. לא מחובר: הקישור נושא תמונת מצב דחוסה (`#`), והאישור חוזר עם קוד ביקורת (FNV).
- התנגשות בין מכשירים מזוהה לפי מספר גרסה, ולא נדרסת בשקט.
- כל סכום וכל סיכון נגזרים מהנתונים. אין מספרים קשיחים בממשק.
